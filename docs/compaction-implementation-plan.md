# 压缩快照实施计划

状态：已实现，自动化检查与一次性功能验证通过；交互式会话验收未执行。

配套设计：[压缩快照与发送上下文设计](compaction-checkpoint-design.md)。本文下的逐项完成情况已按实际结果记录在第 8、9 节。

## 1. 实施结果

实施完成后，插件自主完成以下过程：

```text
确定当前分支前沿和保留指针
  -> 从指针开始压缩新增历史
  -> 完成全部 L1 与连锁提升
  -> 保存 sidecar，再激活内存状态
  -> 整理本次模型消息
  -> 在对话末尾追加仅供展示的摘要
```

模型收到“当前全部顶层块 + 保留原文”，不会收到任何插件展示快照。原始会话和不可变块保留，`context_get` 不变。

本次不接入原生压缩发布，不调用 `ctx.compact()`，不使用 `pi.sendMessage()` 发布展示快照，不改 Pi 核心、提供方、认证或重试，不增加配置项、跨文件提交协议或原生历史迁移。

## 3. 第一步：统一分支指针

修改：`src/types.ts`、`src/state.ts`、`src/mapping.ts`，以及 `src/compress.ts` 中的分支前沿登记函数。

### 数据约定

在现有 `PluginState` 中增加：

```typescript
firstKeptEntryIdByBranch?: Record<string, string>;
```

键与 `topLevelBlockIdsByBranch` 使用相同的活动路径 entry 锚点，值为第一条保留 entry 的 ID。不增加另一个可独立覆盖的全局指针字段。

- 沿用 schemaVersion 4，新增字段按存在时校验，不编写版本迁移或旧版执行分支。
- 无指针记录时，统一从当前前沿的连续覆盖范围求出起点；没有活动块时，从当前可见历史第一条可压缩 entry 开始。
- 已有指针时，必须属于当前活动路径，并与该前沿的覆盖边界一致。
- 前沿和指针从同一锚点取得，不能分别寻找两个“最近记录”后拼起来。
- 只允许从最早历史连续覆盖到最后一个活动块；发现未压缩空隙不能直接以末块末尾作为前缀终点，不删除空隙中的原文，应报告无法按完整前缀继续。
- 不修改不可变块，不新增 ID 序列或哈希记录，不从展示快照读取有效指针。

### 实施动作

1. 在活动前沿选择位置增加一个共享的保留边界解析函数，让选段、发送投影和状态显示使用同一结果。
2. 在 `scopeToActiveBranch()` 隔离候选状态时，同时处理指针索引，避免改动输入状态。
3. 在 `rememberBranchFrontier()` 登记根前沿与内部前沿时，用相同锚点登记指针；不以即将追加的展示 entry 作为必须预先存在的锚点。
4. `loadState()` 保留现有块数据校验；指针的字符串结构在加载时校验，路径与覆盖关系在选择活动分支时校验。
5. `saveState()` 仍一次保存完整候选状态，调用方仍在成功后才替换内存。

完成条件：能够从一个当前分支状态明确得到顶层块、前沿锚点和第一条保留 entry；分支变化时三者一起变化。

## 4. 第二步：改为指针驱动的增量选段

修改：`src/compress.ts`、`src/compactTool.ts`。

### 自动压缩

1. `currentContextEntries()` 继续以 Pi 当前可见 entry 为扫描来源；不改成扫描整个磁盘历史。
2. `sourceEntries()` 及参考材料构造明确排除 `auto-compact-snapshot` 展示 entry；原生 `compaction` 继续排除于目标与参考材料。
3. `runAutoCompression()` 从解析出的保留指针位置推进，不再次扫描已由旧块表示的前缀，不从最近展示快照之后起步。
4. 沿用现有真实请求预算、完整轮次边界、工具调用关系和保留尾部规则；摘要继续禁止 `Goal`，不新增 Goal 源 entry 识别机制。一次预算放不下时继续逐段生成。
5. 每个新 L1 进入本操作的候选前沿，供后续段作为参考；最后完成所有连锁提升。
6. 从最终完整覆盖范围之后查找第一条保留 entry，更新候选指针。先按 entry 顺序定位，再按模型消息规则投影，不能先丢掉元数据后猜指针。
7. 没有可压缩完整前缀时返回 `skipped`；不为了推进指针而压缩受保护尾部。取消及失败沿用当前不提交部分状态的机制。

### 手动压缩

保留 `startId`、`endId`、`focus` 参数，不增加新参数或兼容分支。

- `startId` 必须对应保留指针起的第一条实际可压缩源 entry；指针前后的纯元数据及展示 entry 不要求用户手动指定为源正文。
- 在 `runManualCompression()` 中先检查此前缀条件，再执行现有完整边界、重叠和工具结果检查。
- 若调用跳过最早未压缩原文，明确拒绝并返回应使用的起点，不自动丢弃此前原文。
- `endId` 沿用完整边界调整规则，不能越过受保护尾部。
- 同步工具 label、description、promptSnippet、promptGuidelines 和参数描述，明确“提前压缩最早未压缩前缀”。

完成条件：两次压缩中，第二次 `TARGET_RANGE` 只含旧指针到新结束位置的新增原文；旧块只在必要的参考或合并请求中出现，展示快照完全不出现。

## 5. 第三步：统一发送投影

修改：`src/mapping.ts`、`src/index.ts` 中调用投影的路径。

1. 复用现有 entry 范围映射，不靠摘要文本或 `role=user` 识别压缩内容。
2. 正常前缀状态按“全部当前顶层卡片 + 保留原文尾部”生成发送结果；每个顶层块只生成一张卡片。
3. `projectMessages()` 和 `projectSessionEntries()` 共用相同前沿与保留边界规则，避免 footer、压缩预算及真实请求各算一套。
4. 保留 `event.messages` 中压缩区外的注入内容，不用 `getBranch()` 重新投影后直接覆盖整份事件消息。
5. 维持压缩区内部及块间插入消息的排除规则；保留区中的消息内容、顺序和工具调用 ID 不变。
6. 展示 entry 本来不产生模型消息；相关计数、源 entry 扫描和参考材料也明确排除它。不得用全局删除 `compactionSummary` 的办法替代这条规则。
7. 压缩触发前后的占用计算、状态命令和 footer 使用最终投影的 token 估算。

已有原生摘要而其历史尚未由插件块表示时，保留现有可见表示，不在本次实现接管或迁移。这不是正常插件流程中的展示快照，不适用无条件删除规则。

完成条件：即使原文尾部夹着多个旧展示 entry，模型仍只收到一份当前卡片，普通消息不丢失也不重复。

## 6. 第四步：追加末尾展示并接通所有入口

修改：`src/types.ts`、`src/tui.ts`、`src/index.ts`、`src/compactTool.ts`、`src/adjustTool.ts`。

### 快照格式与渲染

定义一个仅用于展示的数据类型：

```typescript
interface CompactSnapshotData {
  topLevelBlockIds: string[];
  firstKeptEntryId: string;
  cardsText: string;
  tokensBefore: number;
  tokensAfter: number;
}
```

时间和 entry ID 使用 Pi 自带字段，不增加提交编号或成功标记。`cardsText` 直接组合当前全部顶层块的已有卡片，不额外调用摘要模型。

注册 `auto-compact-snapshot` 的 entry renderer：默认显示压缩前后 token、块数量和保留起点；展开显示当次完整卡片。复用现有 TUI 组件与块卡片格式，避免另建一套摘要模板。展示可以折叠，但不能截断持久化的摘要正文。

### 时序

不在通用 `commitState()` 或 `finishCompression()` 中无条件追加 entry。给成功入口提供一个明确的展示追加动作，在最后一次真实路径校验之后调用。

`context` 自动触发路径采用固定顺序：

1. 捕获现有 `operationKey`，运行压缩并提交 sidecar。
2. 继续用现有完整路径检查确认没有真实会话切换。
3. 使用提交后的状态构造 `refreshedProjected`，计算 footer 占用。
4. 同步追加快照，更新当前会话识别缓存，不在追加与返回之间再等待异步工作。
5. 返回第 3 步构造的消息，不能因自己的追加改变 leaf ID 而返回空结果或压缩前上下文。

普通命令和工具在提交后、完成通知前执行最后一次路径检查，再追加快照。已有分支前沿登记在操作时的分支锚点上，展示 entry 作为其后代继承；不为展示追加再写一遍 sidecar。

追加条件是实际发送的顶层卡片或保留指针变化。仅内部子树变化而二者不变时，不重复追加；不能用 `createdBlocks.length` 判断，因为拆分及复用旧块也可能改变顶层卡片。

### 入口清单

| 入口 | 追加规则 |
| --- | --- |
| `context` 阈值触发 | 本次请求新投影构造完成后，满足追加条件时追加一次 |
| `/auto-compact` 手动命令 | 成功提交且满足追加条件时追加一次 |
| `compact_context` | 成功提交且满足追加条件时追加一次 |
| `adjust_context_blocks` | 成功改变顶层卡片后追加一次 |
| 块树界面的合并、拆分 | 顶层卡片改变后追加一次，即使指针不变或没有新块 |
| 意外到达的原生 threshold/overflow 钩子 | 仍由插件处理并取消原生行为，满足追加条件时展示 |
| 无变化、失败、取消、仅恢复会话 | 不追加快照 |

追加失败时记录展示告警，保留已提交状态，不改判为摘要失败，不回滚、不自动重放。没有交互式 TUI 的模式不影响有效状态或消息投影；展示 entry 可以持久化，但不调用仅 TUI 可用的交互 API。

完成条件：顶层卡片或指针变化时最多追加一条快照；合并或拆分改变顶层卡片时也显示更新后的全部块；触发压缩的当前请求立刻使用新投影。

## 9. 实施分批与完成标准

按第 3 至第 8 节顺序完成，建议分三批检查改动：

1. 指针与增量选段，包括手动前缀语义。
2. 统一投影、末尾展示和全部调用入口。
3. 生命周期、可观测性、现有检查和文档同步。

每批先确认类型检查和受影响的现有检查结果，再继续后续集成。最终必须同时满足：

- sidecar 决定唯一有效块树与指针，展示历史不参与恢复决策。
- 新增历史按连续前缀压缩，旧展示不成为目标、参考或发送消息。
- 当前全部顶层块在本次请求中只表示一次，保留原文内容及顺序不变。
