# 压缩快照与发送上下文设计

状态：已实现。自动化检查（`npm run typecheck`、`npm test`、`npm pack --dry-run`）和一次性功能验证脚本均通过；交互式会话中的真人验收（真实自动触发、Esc 取消、fork/resume 界面、快照展开显示）尚未执行。

本文记录已澄清的目标行为；具体文件改动与验收记录见 [实施计划](compaction-implementation-plan.md)。

## 1. 目标与边界

插件继续自主触发、选段、生成摘要、维护块树，并在 `context` 事件中整理本次发给模型的消息。只借鉴 Pi 的“摘要 + 保留指针”思路，不执行 Pi 原生压缩生命周期。

正常插件会话的模型输入顺序为：

```text
系统提示词 -> 当前全部顶层块卡片 -> 未压缩原文尾部
```

系统提示词、AGENTS.md、工具和 Skill 描述仍由 Pi 管理，不属于本插件的历史选段。压缩区外由其他扩展注入的消息继续保留。

明确不做：

- 不调用 `ctx.compact()`，不生成真正的原生 `CompactionEntry`，不通过原生钩子发布摘要。
- 不修改 Pi 核心，不直接改写会话 JSONL，不接管提供方请求客户端。
- 不增加 sidecar 与展示记录之间的提交协议、成功标记或故障恢复系统。
- 不迁移已有原生压缩历史，不增加兼容执行分支或新的配置开关。

保留原生压缩拦截。插件正常压缩只走自己的入口，失败也不回退到原生压缩。

## 2. 三种数据的职责

| 数据 | 存放位置 | 职责 |
| --- | --- | --- |
| 不可变块、当前分支前沿、保留指针 | `<session>.autocompact.json` | 唯一有效状态，决定下一次压缩及模型输入 |
| 压缩展示快照 | 会话中的 `custom` entry，`customType = auto-compact-snapshot` | 保存当次全部顶层块文本和指针，供对话末尾展示及历史查看 |
| 原始 entry | 原会话文件 | 原文取回和分支校验，不因压缩而删除 |

“前沿”指当前活动分支选择的顶层块及内部子块列表。

展示快照通过 `pi.appendEntry()` 写入，通过 `pi.registerEntryRenderer()` 显示。Pi 明确规定这种 `CustomEntry` 不参与模型上下文，因此不用 `pi.sendMessage()`。

最新展示快照也不直接发给模型。模型使用的卡片始终从 sidecar 当前状态生成；快照只保存该状态的一份展示结果，不用于恢复、覆盖或决定有效状态。

## 3. 保留指针

`firstKeptEntryId` 指向已压缩完整前缀之后第一条保留 entry，不是屏幕上下一条消息，也不是“最新展示快照之后”的位置。

- 首次压缩从当前可见历史中第一条参与模型上下文的 entry 开始。
- 后续压缩从当前分支的保留指针开始，直到新的完整结束边界。
- 指针按当前分支前沿保存和选择，不能跨分支共用一个全局值。
- entry 不产生模型消息也可以成为指针；读取摘要材料时再过滤无正文的元数据和展示快照。
- 指针只能越过已完整表示的连续历史，不能越过未压缩空隙。
- 仅合并或拆分现有块时，覆盖范围不变，指针也不变。

块边界仍只记录 `startEntryId`、`endEntryId`，不记录整个区间的 ID 序列，不增加哈希校验。摘要继续禁止 `Goal`，当前未完成尾部继续保留；不在本次增加新的 Goal 源 entry 识别机制。

## 4. 首次与增量压缩

一次操作的顺序：

1. 选择当前分支的块前沿与保留指针，确定可压缩的完整前缀。
2. 只将本次新增的未压缩原文作为 `TARGET_RANGE`；按真实摘要请求预算顺序分段。
3. 复用当前参考上下文生成 L1 块；每个新块成为后续段的参考，完成全部连锁合并和升层。
4. 根据最终成功覆盖的范围计算新指针，得到完整候选状态。
5. 校验取消信号与会话路径，保存 sidecar 成功后才替换内存状态。
6. 若本次在 `context` 中触发，先校验当前路径并构造本次请求的新投影，再追加展示快照，返回已经构造好的消息。
7. 其他入口在成功提交后追加展示快照，更新进度与 footer。

快照包含当次全部顶层块，而非仅本次新增的 L1。只有实际发送的顶层卡片或保留指针变化时才追加；仅内部子树变化而发送内容不变，不重复追加。组合卡片不需要额外模型调用；只有既有合并规则要求生成更高层块时才请求摘要。

例子中 `K1`、`K2` 是当前模型卡片集合，`S1`、`S2` 是只供展示的快照：

```text
初始文件：A -> B -> C
压缩 A 后：A -> B -> C -> S1
有效状态：K1 表示 A，保留指针为 B
本次发送：K1 -> B -> C

追加 D，再压缩 B：
文件：A -> B -> C -> S1 -> D -> S2
有效状态：K2 表示 A、B，保留指针为 C
本次发送：K2 -> C -> D
```

无论新指针是否越过 S1，S1 和 S2 都不作为消息发送，也不作为新增原文或重复参考材料摘要。

## 5. 发送前整理

`context` 是实际请求消息的整理入口，不另建发送管线。

1. 从 sidecar 解析当前活动分支的顶层块与保留指针。
2. 按块的原文顺序生成当前卡片，每个顶层块只出现一次。
3. 保留指针之后的原文消息保持原始顺序、内容和工具调用关系。
4. 展示快照依据 entry 类型和 `customType` 识别，不依据摘要文本、角色或屏幕位置猜测。
5. 压缩区内部及块间后来注入的消息继续排除；压缩区外的注入消息继续保留，不通过从磁盘重建全部消息来覆盖 `event.messages`。
6. footer、自动阈值判断和实际发送共用同一投影口径。

不要误删普通用户消息、工具返回的摘要文字、其他扩展消息或 `branch_summary`。`context_get` 仍从完整当前分支分页取回原文，`rawEntryJson` 保留完整字段。

## 6. 分支、取消与展示时序

沿用现有分支前沿索引选择活动路径。指针与前沿必须在同一分支锚点解析；恢复、tree、fork 和 clone 继续沿用现有状态选择与继承流程，不从展示快照重建状态。

沿用单一活动操作、合并取消信号、摘要全部完成后提交、sidecar 先保存后激活的现有机制。取消只返回 `skipped`；摘要或 sidecar 保存失败不提交半成品。

`appendEntry()` 会改变 leaf ID。当前代码在摘要完成后用 `currentSessionKey()` 校验路径，因此不能在通用 `commitState()` 内立即追加快照，否则可能把插件自己的追加误判成会话切换。

具体处理为：触发压缩的 `context` 路径先完成真实路径校验和新投影，再同步追加展示 entry 并返回已构造的消息；追加后刷新本地会话识别缓存。其他入口也在最后一次路径校验之后追加。不能删除真实的会话变化校验，不能忽略任意 leaf 变化。

展示追加失败只记录明确告警，不撤销已经成功提交的 sidecar，也不把旧快照恢复成有效状态。不重试发布、不重放快照、不增加第二套提交记录。

## 7. 原生压缩历史的范围说明

此前通过内存验证观察到：在当时核对的 Pi 指针式实现中，旧 `CompactionEntry` 落入新保留区间时可能再次成为模型消息。这是本方案的讨论背景，不是本方案需要调用或修补的代码路径，也不代表所有 Pi 版本。

本设计从插件自己的入口开始解决问题：不再创建原生压缩记录，所有插件展示快照天然不参与模型上下文。

对于已经存在原生压缩的会话，本次不增加迁移或接管算法。不能因为发现 `compaction` / `compactionSummary` 就全局删除；尚未由插件块覆盖的原生摘要可能是该段历史唯一的可见表示，应保留现有行为。原生 `compaction` 仍不作为插件摘要目标或 `REFERENCE_CONTEXT`。

## 8. 不变项与验收

以下机制保持不变：不可变块仓库、有序 L1 叶子身份复用、k+1 触发合并、稳定树投影、摘要预算、图片传递、禁止 Goal、卡片上限、认证与重试、原文取回。

验收重点：首次压缩、连续两次压缩、保留区间内多个展示快照、指针不动的合并或拆分、触发压缩的当前请求、正常恢复及分支切换。具体操作和可观察结果见实施计划。

日志只记录分支锚点、指针、块 ID、数量、token 估算、耗时与错误；不主动记录摘要正文、原文、图片或认证信息。

## 9. 实现范围

已按本设计落地：分支保留指针、指针驱动的连续前缀选段、手动前缀约束、统一发送投影、末尾展示快照及全部调用入口、生命周期与可观测性。sidecar 仍是唯一有效状态；实现不调用 `ctx.compact()`、不生成原生 `CompactionEntry`、不使用 `pi.sendMessage()` 发布展示记录、不改 Pi 核心、提供方、认证或重试，不增加配置项、跨文件提交协议或原生历史迁移。README 与 AGENTS.md 已同步。

已知未完成：交互式会话中的实际自动触发、Esc 取消、fork/resume 与快照展开显示未做真人验收；已有的原生压缩历史仍不接管、不迁移。
